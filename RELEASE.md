# Выпуск v41 — что сделать владельцу

Порядок: **Worker → сайт (и удалить один файл) → проверка на телефонах.**
Главное в v41:

- номер (личная ссылка) закреплён за ключом владельца — чужое устройство
  на нём больше не регистрируется;
- push о звонках при закрытом приложении заработал впервые с v20;
- эхоподавление в режиме «Авто»: в наушниках выключено, на динамике
  включено.

Подробно — [AUDIT-v41.md](AUDIT-v41.md). Worker v41 совместим с
клиентами v40 и старше, поэтому выкатывайте его первым: защита номера и
push заработают сразу, даже у тех, кто ещё не обновил сайт.

## 1. Worker v41

```bash
npx wrangler deploy        # из корня: wrangler.toml → worker/worker.js
```

Проверка: `https://<ваш-worker>/health` →
`"v": 41, "owner": true, "pushCrypto": "v41"` (и, как раньше,
`"push": true, "devices": true, "revoke": true`). `"turn": false` —
нормально: TURN идёт из `config.js`.

Новых секретов, привязок и миграций нет. Что изменится сразу после
деплоя:

- **Push начнёт доходить.** До v41 сервер не мог зашифровать ни одно
  уведомление (ошибка с v20). Если вы включали «Push-уведомления о
  звонках», а звонки при закрытом приложении не приходили, причина была в
  сервере, а не в телефоне. Сохранённые подписки заработают сами.
- **Номер закреплён за ключом**, который первым зарегистрировался на
  сервере. Обычно это вы: ключ записался при создании номера. Если на
  номере были чужие устройства, сервер удалит их при следующем запуске
  приложения на любом вашем устройстве.
- Если в «Мой номер» появилась надпись «Эта личная ссылка на сервере
  закреплена за другим ключом», номер занят чужим ключом. Нажмите
  «Сменить номер (новая ссылка)» и разошлите новую ссылку. Другого выхода
  нет: сервер не может знать, какой из двух ключей настоящий.

## 2. Публикация сайта

**Вариант А — git (рекомендую: переносит удаления и скрытые файлы).**

```bash
git clone https://github.com/qwkejkqwje1/zvonochek && cd zvonochek
git apply --binary ../zvonochek-v41.patch
git add -A && git commit -m "41v" && git push
```

**Вариант Б — веб-интерфейс GitHub.**

1. «Add file» → «Upload files» → перетащите содержимое архива → «Commit
   changes».
2. **Удалите `vendor/mqtt.min.js`:** откройте файл → «…» → «Delete file» →
   «Commit changes». Загрузка через браузер не удаляет файлы. Из-за этого
   файл пережил v40, и `npm test` падал.
3. Проверьте, что появились скрытые файлы `.github/workflows/ci.yml` и
   `.gitignore`: при перетаскивании браузер может их пропустить. Если их
   нет, «Add file» → «Create new file», введите имя с точкой
   (`.github/workflows/ci.yml`) и вставьте содержимое из архива.

Проверка: `…/zvonochek/version.json` → `{"v":41}`. Во вкладке
**Actions** — прогон «tests» (5–10 минут): юнит-тесты, затем e2e с
локальным Worker. Красный прогон не мешает сайту, но покажет, что сломано.
Service Worker сменит кэш на `zvonochek-v41`; открытые вкладки перейдут на
новую версию при следующем открытии.

## 3. Проверка на телефонах (30 минут)

Тестируйте **из разных комнат или в наушниках**. Если два устройства в
одной комнате, ваш живой голос попадает во второй микрофон напрямую, и
никакое эхоподавление его не уберёт.

1. **«Авто» понимает, куда идёт звук.** «Настройки» → «Обработка звука» →
   «Эхоподавление: Авто». Под списком — строка «Сейчас: …».
   - Android без наушников: «звук из динамика — эхоподавление включено».
     Подключите проводные или Bluetooth-наушники: «наушники или
     гарнитура — эхоподавление выключено». В звонке при этом появится
     уведомление.
   - iPhone: с AirPods или гарнитурой — «наушники», без них — «динамик».
   - Если написано «не удалось понять», эхоподавление включено (так
     безопаснее для собеседника). Если вы в наушниках, выберите
     «Выключено» и пришлите название наушников: добавлю его в
     распознавание.
2. **Портит ли AEC голос — сравнение вдвоём.** Эффект AEC слышит
   собеседник, а не вы, поэтому оценивает он. Во время звонка откройте
   меню звука и переключайте галочку «Эхоподавление», повторяя одну и ту
   же фразу.
   - Вы в наушниках: AEC выключен — должно звучать не хуже, обычно
     чище, особенно когда говорите одновременно.
   - Вы на динамике: AEC выключен — собеседник слышит эхо своего голоса,
     включён — эха нет. Здесь AEC нужен.
3. **«Проверить микрофон»** (в лобби перед звонком) записывает 5 секунд
   и проигрывает запись — так вас услышит собеседник (без сжатия Opus).
4. **Push при закрытом приложении.**
   - Android: «Мой номер» → «Push-уведомления о звонках» → разрешить.
     Закройте приложение, заблокируйте экран и позвоните на личную ссылку
     с другого устройства. Должно прийти уведомление с вибрацией;
     «Ответить» — и вы сразу в звонке.
   - iPhone: только с иконки на главном экране (iOS 16.4 и новее).
   - Не отвечайте: после звонка останется тихое «Пропущенный звонок».
5. **Перезвон.** Позвоните, положите трубку и сразу позвоните снова.
   Звонок должен соединиться за 1–3 секунды, голос — слышен в обе
   стороны.
6. **Соседство с TorrClient.** Откройте TorrClient в соседней вкладке,
   сверните Звоночек и позвоните на личную ссылку: уведомление о звонке
   должно появиться (раньше вкладка TorrClient его глушила). «Стереть
   всё» проверяйте только на запасном браузере с тестовым профилем:
   после него настройки TorrClient должны остаться.
7. **Два устройства (если подключены).** Звонок на номер звонит на обоих.
   «Стереть всё» на подключённом устройстве только отвязывает его, а
   номер продолжает работать на основном.

## 4. Звонки при закрытом приложении — на каждом устройстве

1. **Android:** «Мой номер» → «Push-уведомления о звонках» (или кнопка
   «Включить» на плашке во вкладке «Звонки») → разрешить. На Xiaomi,
   Huawei, Honor и Samsung с агрессивной экономией батареи исключите
   Chrome из оптимизации батареи, иначе push может опаздывать.
2. **iPhone:** сначала «Поделиться» → «На экран Домой», откройте
   ZVONochek с иконки и только потом включайте уведомления (iOS ≥ 16.4; в
   Safari-вкладке push на iPhone не работает).
3. **ПК:** браузер должен быть запущен (вкладку можно закрыть).

На **выключенный** телефон звонок не дойдёт ни в одном мессенджере.
Звонок ждёт, только пока идёт вызов (до 90 с), потом попадает в
«Пропущенные» (хранятся 24 ч).

## 5. Второе устройство (телефон + ПК)

Как в v39: на новом устройстве «Мой номер» → «Подключить к моему
профилю»; на основном — «Мои устройства» → «Подключить устройство» → QR
или код → сверить 4 слова. Код и QR никому не пересылайте. Подключать,
отвязывать, менять и гасить номер можно только на основном устройстве
(или там, где введена фраза восстановления); с v41 это проверяет и
сервер. Украли устройство: на основном «Отвязать», затем «Сменить номер».

## 6. TURN — крайнее средство

Без изменений с v40. Звонок начинается без TURN. Логины из `config.js`
включаются, только если прямой путь не поднялся за 6 с (пока ICE явно
продвигается, ждём до 14 с), соединение упало, после смены сети не
нашлось прямого пути или выбран режим «только TURN». Логины видны всем в
публичном репозитории. Если чужие выберут квоту, зарегистрируйтесь
бесплатно на metered.ca или expressturn.com и впишите новые логины в
`config.js` или в секреты Worker (`TURN_URLS`, `TURN_USERNAME`,
`TURN_CREDENTIAL`, см. [worker/README.md](worker/README.md)).

## 7. Откат

- **Сайт:** залить архив v40 (`vendor/mqtt.min.js` не возвращать). Настройки
  совместимы: v41 продолжает записывать `zvEcho` для v40.
- **Worker:** откатывать не рекомендую. Worker v40 снова пустит чужие
  устройства на номер и опять сломает push. Если всё же нужно —
  `npx wrangler rollback` (Cloudflare хранит прошлые версии). Данные
  совместимы: запись владельца v40 просто не проверяет.

Перед публикацией разработчику: `npm ci && npm test`, при наличии
Chromium — `npm run worker:dev` и `npm run e2e`. То же самое делает CI
(`.github/workflows/ci.yml`) на каждый push.
