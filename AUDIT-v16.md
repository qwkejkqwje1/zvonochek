# ZVONochek v16 — групповые звонки и групповой чат

Дата: 27 октября 2026. Повод: полевой тест v14 + запрос владельца на звонки
на несколько человек и групповые чаты.

## Разбор полевого теста v14 (лог владельца, собеседник StarSleep)

Что подтвердилось:
- Direct P2P по LAN поднялся за ~1 секунду, маршрут «напрямую (LAN), UDP».
- Мост 2.0 на WebCodecs реально включился («кадры 20 мс») — альтернативный
  метод работает в Chromium.
- Транспорты: MQTT 2/5, Worker WS, Nostr 7/9 — гонка каналов здорова.

Что нашлось:
1. **Статический TURN-резерв в тесте не подключился**: «TURN недоступен
   (Worker: без TURN)», в причинах нет «Статический резерв из config: есть» —
   в протестированной сборке config.js был без EXTRA_ICE_SERVERS (загрузка
   финального config на GitHub ещё шла). После загрузки проверить повторно.
2. **Режим сети стоял «мост»** (сохранённая настройка): поэтому мост включился
   при идеальном LAN-direct. Для обычных звонков нужен режим «Авто».
3. **ICE restart на 40-й секунде** с offer «0 маршрутов» — быстрый SDP ушёл
   до досбора кандидатов; кандидаты при этом идут отдельным потоком (cand),
   соединение не пострадало, но в логе выглядит тревожно.
4. Счётчик «мост 0» при включённом мосте: в v16 счёт продублирован в месте
   фактического старта рекордера моста.

## Групповой режим (новое в v16)

Архитектура — mesh поверх существующего сигналинга, без переписывания 1:1:

- Первый собеседник — как раньше, основным движком app.js (со всем: мостом,
  статистикой, кодом безопасности).
- Участники сверх второго обслуживаются отдельным модулем `group.js`:
  отдельное RTCPeerConnection на каждого (perfect negotiation, polite по id),
  видеоплитки справа (`#tiles`), звук каждого — в общий аудиотракт
  (громкость 0–200% работает и для группы), при недоступности тракта — фолбэк
  звуком из плитки.
- Лимит комнаты: 6 участников (я + 5). Сверх — честный `full`, как раньше.
- Групповой чат: при 3+ участниках отправка идёт широковещательно типом
  `g_chat` через E2EE-сигналинг с именем отправителя; 1:1 чат не изменился.
- Мост при 3+ участниках отключается автоматически (он 1:1 по природе);
  для группы работают direct и ленивый TURN (при failed групповой сессии
  TURN догружается так же, как в основном движке).
- Смена устройств/камеры/экрана в звонке обновляет треки и в групповых
  сессиях (`refreshTracks` из `setSendTrack`).

Ограничения v1 группового режима (осознанные):
- Если основной собеседник вышел, групповые участники не «повышаются»
  в основные: статистика, код безопасности и мост остаются про первого.
- Файлы в группе не передаются (только 1:1 DataChannel, как раньше).
- Mesh честно масштабируется до ~4 видео / 6 аудио; дальше нужен SFU,
  которого у проекта нет и на бесплатной инфраструктуре не будет.
- Видео доп. участников — плитки-превью без отдельного управления звуком.

Проверка: синтаксис всех JS, 0 отсутствующих id, HTTP-отдача v16 — 200.
Живой тест нужен на 3 устройствах: A+B в звонке, C заходит по ссылке —
у A и B должна появиться плитка C, у C — плитка второго участника,
групповой чат должен дойти до всех троих.
