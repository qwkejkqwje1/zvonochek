# ZVONochek v23 — проба окружения при загрузке: диагноз поимён, владелец предупреждается заранее

Дата: 2026-10-30. База: v22 (диагностическая сборка). GitHub не пушился, Cloudflare не деплоился.

## Диагноз (получен от владельца благодаря v22)

Баннер v22 при нажатии «Создать мою ссылку для звонков» показал тост:

> «Не удалось создать ссылку: crypto.subtle.generateKeyPair is not a function»

То есть в браузере владельца WebCrypto **присутствует**, но метод `generateKeyPair` **отсутствует**. При этом звонки у владельца работают: звонковый путь (`deriveRoom`) обходится `importKey`/`deriveKey`, а генерация пары ключей нужна только личной ссылке (identity.js, ECDSA P-256) и чату (ключ устройства). Поэтому обе кнопки v21 «молчали», а звонки — нет. Точный браузер/контекст владельца по-прежнему неизвестен — v23 снимает эту неизвестность пробой (см. ниже) и больше не заставляет гадать.

## Что сделано в v23

Всё — в `zvdiag.js` (классический скрипт ранней диагностики, подключается до модулей):

1. **Проба окружения** `window.__zvProbe()` → `{ua, secure, subtle, gen, sign, imp, enc}`:
   укороченный `navigator.userAgent` (первые 80 символов), `window.isSecureContext`,
   `typeof crypto.subtle` и `typeof` методов `generateKeyPair` / `sign` / `importKey` / `encrypt`.
   Компактная сводка — `window.__zvEnvText()`, одна строка.
2. **Сводка окружения в каждом баннере**: `window.__zvShowDiag(text)` теперь дописывает
   к тексту приписку ` [окружение: secure=…, subtle=…, generateKeyPair=…, sign=…, importKey=…, encrypt=…, UA: …]`
   (если приписки ещё нет). Любая ошибка из приложения теперь приходит разработчику вместе с окружением.
3. **Проверка при загрузке**: сразу после DOMContentLoaded (а не по нажатию кнопки) — если
   `crypto.subtle` отсутствует или `generateKeyPair` не функция, показывается баннер-предупреждение
   (точный текст ниже). Watchdog загрузки модулей (9 с) и перехват ошибок сохранены без изменений.
4. **Закрытие баннера**: по клику на баннер он скрывается (обработчик на элементе `#zvDiag`,
   вешается один раз; в конце текста баннера дорисовывается «✕» как подсказка).

Версия поднята до v23 по конвенции проекта: `version.json` {"v":23}, `?v=23` во всех импортах
и тегах (совпадений `?v=22` в исходниках не осталось), `CACHE_NAME 'zvonochek-v23'`, `APP_VERSION 23`.

## Точный текст баннера при загрузке в проблемном окружении

> Этот браузер не даёт генерировать ключи шифрования (нет crypto.subtle.generateKeyPair) — личная ссылка и чаты здесь не заработают, звонки могут работать. Откройте сайт в актуальном Chrome/Firefox/Safari по https. [окружение: secure=…, subtle=…, generateKeyPair=undefined, sign=…, importKey=…, encrypt=…, UA: …] ✕

Что он означает: окружение владельца (браузер/режим/контекст страницы) не предоставляет полную
WebCrypto — создать идентичность и ключи чата на этом устройстве нельзя физически, это не баг
приложения и не воркер. Лечится сменой браузера/контекста (актуальный Chrome/Firefox/Safari,
страница по https), а сводка окружения в баннере позволяет разработчику назвать точную причину
по скриншоту владельца.

  `generateKeyPair=undefined` в сводке; (B) полный WebCrypto → баннера нет; (C) нет subtle → баннер, `subtle=undefined`.

- Регрессия звонков: `git diff` от базы v20 по `signaling.js` и `group.js` — **пуст полностью**.

## Что НЕ сделано / осталось

- Корневая причина окружения владельца (какой именно браузер/режим режет generateKeyPair) не
  называна — её покажет сводка окружения на её скриншоте v23; фикс на стороне приложения для
  такого окружения невозможен в принципе, только предупреждение (оно и сделано).
- Деплой Worker v21+ (ChatRoom, миграция) и секрет VAPID в Cloudflare — по-прежнему ждут
  отдельного шага с входом владельца; серверная часть чата в проде не заработала.
- Фазы 2 (ссылка+PIN) и 3 (эпохи) мессенджера — без изменений, только спроектированы в техплане v21.
