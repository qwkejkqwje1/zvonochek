# ZVONochek v14 — что сделано по итогам оценки и разбора DeepSeek

База: v13 (см. AUDIT-v13.md). Дата: 27 октября 2026.

## Лестница маршрутов вместо «всё сразу» (экономия TURN)

- Статические TURN-креды (Metered/ExpressTURN): сначала были удалены из клиента,
  но 27.10.2026 **решением владельца возвращены** в `config.js` как резервный
  источник — чтобы при необходимости звонки могли идти через них, пока в Worker
  не настроены эфемерные креды. Компромисс осознанный: креды видны в исходниках,
  зато они теперь используются только лениво, а не на каждом звонке.
- `loadIce()` теперь отдаёт только STUN. TURN — `ensureTurnLoaded()`:
  эфемерные креды из Worker `/turn`, догрузка через `setConfiguration + restartIce`
  по трём триггерам: direct не встал за 6 с; ICE `failed`; ручной режим «только TURN».
- De-escalation: при смене сети TURN сбрасывается, сначала снова direct,
  TURN возвращается лениво, только если direct не встал.
- Ежечасный рефреш кред (фикс TTL из v13) теперь работает только когда TURN
  реально загружен.
- Честное следствие: без настроенного в Worker TURN проект работает без TURN
  вообще — direct + мост. Для видео при symmetric NAT это ограничение остаётся
  (мост видео не заменяет) — в диагностике это теперь видно счётчиками маршрутов.

## Инфраструктура

- STUN 6 → 10 (Google ×5, Cloudflare, Nextcloud :443, Metered :80,
  stunserver.org, Twilio). STUN не пропускает медиа, его пул расширять дёшево.
- MQTT 4 → 5 брокеров (+Eclipse WSS 443). Nostr 6 → 9 реле.
- Реалистичный потолок «10/10» без своих серверов недостижим: публичные брокеры
  и реле — чужая добрая воля. Следующий качественный шаг — второй собственный
  Worker/домен как резервный сигналинг, а не ещё больше публичных адресов.

## Аудиотракт: спорные функции убраны из дефолта

По решению владельца: VAD-гейт (главный подозреваемый в «пропаданиях» вместе
с DTX и засыпанием AudioContext) больше не стоит на пути звука по умолчанию.
Дефолт — открытый микрофон; VAD/PTT — ручные опции в настройках. DTX удалён
в v13, обработка/компрессор — опциональны с v13. AudioContext оставлен только
как усилитель громкости 0–200% со сторожем из v13: без него не работает
регулировка громкости собеседника.

## Мост 2.0 (WebCodecs) — альтернативный метод

- Отправка: MediaStreamTrackProcessor → AudioEncoder Opus 24 кбит/с, кадры
  20 мс, пачки ~120 мс по сигналингу (тип `voice2`, длина-префиксы, base64).
- Приём: AudioDecoder → плейбек через существующий исходящий тракт,
  джиттер-буфер ~0,35 с, расписание по AudioContext.
- Совместимость: обмен флагом `bc` в hello/hi. Chromium↔Chromium — мост 2.0;
  любой другой собеседник — мост 1.0 (MediaRecorder, ускорен до кусков 400 мс).
- Ограничения: WebCodecs-аудио нет в Safari и почти нет в Firefox — поэтому
  это альтернатива, а не замена; через MQTT задержка брокера всё равно
  добавляет свои 100–300 мс, лучший канал для моста 2.0 — Worker WS.

## Версия на виду

`APP_VERSION`/`APP_BUILD` — единый источник; плейсхолдеры `data-ver`/`data-build`
на главной (бейдж + подпись), в лобби и в карточке подключения; в начале звонка
версия пишется системным сообщением в чат (и у P2P, и у моста).

## Не проверялось вживую

Нужны два устройства и Chromium: мост 2.0 в реальном звонке, ленивый TURN
(с настроенным Worker-TURN), de-escalation при переключении Wi-Fi↔LTE.
Статические проверки пройдены: синтаксис всех JS, 0 отсутствующих id,
баланс CSS, статических TURN-кредов в репозитории не осталось.
