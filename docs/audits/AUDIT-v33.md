# AUDIT v33 — совместимость со старыми браузерами (потолок синтаксиса ES2020)

База: v32 из GitHub main (коммит b47701a «32v») — синк свежим clone,
version.json синка = {"v":32}. Цель v33 — один точечный фикс по живому
инциденту, без функциональных изменений. Воркер НЕ тронут: /health
останется v:32 и после публикации клиента v33 — это нормально, клиент и
воркер версионируются раздельно.

## Инцидент

Гость на Android 9 (Redmi Note 8T, движок класса Chrome 80–84) не смог
войти в звонок: баннер «Модуль приложения не загрузился. Ошибки:
Uncaught SyntaxError: Unexpected token '=' (…/app.js?v=32)». Среда из
баннера: secure=true, subtle=object, generateKeyPair=undefined,
sign/importKey/encrypt — функции (это отдельная известная особенность
окружения, закрыта fallback-ом v24, к этому инциденту отношения не
имеет).

Причина — синтаксис новее ES2020 в клиентском коде. Старый движок
понимает ES2020 (optional chaining ?. и ?? в файле стоят раньше места
падения и парсятся), но не ES2021: один такой оператор валит ВЕСЬ
модуль на этапе парсинга — приложение не стартует вообще, даже его
диагностический баннер рисуется отдельным скриптом zvdiag.js.

ПРАВИЛО ПРОЕКТА с v33: синтаксис клиента — не новее ES2020. Страж —
тест test-compat.mjs (см. ниже); перед публикацией любой следующей
версии он обязателен к прогону.

## Что найдено свипом и исправлено

Сканировались все клиентские JS корня репозитория. Итого найдена
21 конструкция ES2021+ в собственном коде; runtime-API новее ES2020
без guard (.replaceAll, .at, findLast/findLastIndex, Object.hasOwn,
structuredClone) в собственном коде — 0 мест; полей классов и
#private — 0 мест (все совпадения по «#» — URL-фрагменты #k=/#chat=
в строках и комментариях).

| Файл | Конструкция | Кол-во | Замена |
|---|---|---|---|
| app.js | `??=` (S.qLevel / S.qBad / S.qGood, строки 2484–2486) | 3 | `S.qLevel = S.qLevel ?? 0;` и т.д. (семантика `a ??= b` ≡ `a = a ?? b` сохранена точно) |
| app.js | числовые разделители: 10_000, 90_000 | 2 | 10000, 90000 |
| chat.js | числовые разделители: 3600_000, 3_600_000, 20_000 ×2, 30_000, 60_000 ×3 | 8 | те же числа без подчёркиваний |
| crypto.js | 600_000 ×2, 200_000 ×2 (итерации PBKDF2) | 4 | 600000 / 200000 |
| identity.js | 3600_000 | 1 | 3600000 |
| chat-transport.js | 60_000, 3600_000 | 2 | 60000 / 3600000 |
| backup.js | 3600_000 | 1 | 3600000 |
| store.js, signaling.js, group.js, inbox.js, config.js, zvdiag.js, sw.js | — | 0 | чисты уже в v32 |

Числовые разделители — тоже ES2021: acorn-парсинг исходного v32 app.js
с ecmaVersion 2020 падает первой же ошибкой именно на них
(«Identifier directly after number», строка 1772), ??= — следующая
точка отказа. Убираются обе группы, иначе фикс был бы половинчатым.

## Остаточные риски: вендор (НЕ переписывался, по решению аудита)

Acorn с ecmaVersion 2020 НЕ парсит два из трёх вендорных файлов —
это синтаксис ES2022 «поля классов»:

- vendor/secp256k1.js — 8 объявлений полей: class Point (строки
  249–253: static BASE; static ZERO; X; Y; Z;) и class Signature
  (строки 552–554: r; s; recovery;). Парсится только с ecmaVersion
  2022. РИСК ВЫСОКИЙ: файл стоит в СТАТИЧЕСКИХ импортах identity.js,
  signaling.js и chat-transport.js, а identity/signaling импортирует
  app.js — на движке класса Chrome 80–84 граф модулей приложения
  упадёт на этом файле, даже с исправленным app.js. То есть v33
  убирает зафиксированную ошибку инцидента, но полную запускаемость
  на таком старом движке не гарантирует: нужен отдельный шаг —
  ES2020-сборка @noble/secp256k1 (транспиляция полей классов) или
  перевод импорта на ленивый с guard-ом. Решение — за владельцем,
  в объём v33 вендор сознательно не тронут.
- vendor/mqtt.min.js — поля классов в 9 классах (23 объявления,
  напр. class{options;_inflights;constructor…}) + один runtime-вызов
  .at(-1) (ES2022; упадёт только ветка QoS-store при выполнении).
  Парсится только с ecmaVersion 2022. РИСК СРЕДНИЙ и смягчён:
  mqtt — классический скрипт из index.html, его падение не валит
  модули приложения; signaling.js и chat-transport.js обращаются к
  нему через guard-ы (typeof mqtt / globalThis.mqtt?.), старый
  движок теряет только MQTT-канал сигналинга/резерва, остаются
  Worker и Nostr.
- vendor/qrcode.js — чист: парсится как ES2020, запрещённых
  конструкций нет.
