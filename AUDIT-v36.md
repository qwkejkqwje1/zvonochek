# AUDIT v36 — финальный релиз: устойчивость связи, статистика, интерфейс

Дата: 01.11.2026. База: архив v35 (дерево v34 + v35). Живой сайт и Worker на
момент сборки — v32 (`/health` → `v: 32`, `turn: false`).

**Модель угроз владельца:** слежка и анализ трафика со стороны государства,
блокировки, взлом, сбор больших данных. Назначение — личный коммуникатор
для узкого круга, чтобы быстро созвониться и переписываться, когда
Telegram заблокирован. Ограничение — бесплатно.

## Итог проверки

| Проверка | Результат |
|---|---|
| `npm test` — юнит- и статические тесты | 48 / 48 |
| `npm run e2e` — чат и звонок в двух браузерах, 390×844 и 1440×900 | 4 / 4 (локальный Worker v36) |
| Синтаксис: клиент ≤ ES2020, `zvdiag.js` — ES5, `mqtt-lite.js` — ES2017 | ok |
| Полевой прогон на российских сетях и реальных телефонах | **не проводился** |

## Найдено и исправлено

### Критичное

1. **ntfy-канал v35 был мёртв.** Топики длиной 68–73 символа при лимите
   ntfy 64 → `404`, канал молчал без единой ошибки в интерфейсе. Теперь —
   префикс + 48 hex SHA-256 (`ntfy.js`), тесты на длину и формат.
2. **Логины TURN в публичном клиенте.** Metered и ExpressTURN лежали в
   `config.js` открытым текстом: любой мог выбрать квоту, и TURN отказывал
   бы ровно тогда, когда без него звонок не соединяется. Удалены; TURN —
   только из секретов Worker. Старые логины нужно отозвать (RELEASE.md, §2).
3. **Перебор кодов по адресам.** Ключ записи кода/фразы защищал PBKDF2, а
   адрес записи — быстрый SHA-256: видящий адреса (оператор, логи, дамп)
   перебирал коды на GPU со скоростью SHA-256. Схема 2: адрес и ключ — из
   одного PBKDF2 через HKDF; записи ≤ v35 читаются по старому адресу.

### Важное

4. `vendor/mqtt.min.js` (342 КБ, синтаксис ES2022) падал на старых движках —
   MQTT пропадал молча. Заменён своим `mqtt-lite.js` (MQTT 3.1.1, ES2017,
   тесты пакетов и переподключения), пауза переподключения растёт до 30 с.
5. После завершения звонка отложенные обработчики писали в уже закрытый
   сигналинг (`S.sig` = `null`) → исключения. Все отправки — `S.sig?.send`.
6. Досинхронизация N сообщений запускала N полных перерисовок (O(N²)) —
   подвисания на слабых телефонах. `coalesce.js` схлопывает вызовы.
7. ntfy получал каждый пакет, включая ICE-кандидаты, — анонимная квота
   кончалась за минуты. Теперь только рукопожатие, `hello` ≤ 1 раза в 30 с,
   тела > 4096 байт не отправляются (ntfy превратил бы их во вложения).
8. VAPID-ключ был зашит в клиент — на «своём сервере» push не работал бы.
   Ключ берётся у Worker (`/push-key`), подписка на чужой ключ пересоздаётся.
9. `/health` сообщал `turn: true` при неполных секретах (`TURN_URLS` без
   пароля) и `false` при `METERED_API_TOKEN` — условия выровнены с `/turn`.
10. Старый браузер видел пустой экран — теперь экран «обновите браузер».

### Интерфейс и качество

11. Статистика звонка вынесена в чистый модуль `callstats.js` (разбор
    `getStats()` Chrome/Firefox, MOS, запись хода звонка, сводка журнала) и
    `stats-ui.js` (панель качества, журнал, сводка за 30 дней).
12. Чат: локаль времени зафиксирована (`ru-RU`), время списка как в
    Telegram, раскладка личного чата, приветственная карточка, меню с
    иконками, «Копировать текст», двухстрочная панель ответа, уведомления
    с именем собеседника, строка статуса только при проблемах.
13. Тексты: нейтральные по роду системные строки, русские формы числа
    («1 разговор», «2 разговора»), предупреждение о новом устройстве с
    ником и хвостом ключа без некрасивого переноса.
14. Видео собеседника подстраивается под форму экрана; на телефоне превью
    камеры не закрывает карточку подключения.
15. Диагностика показывает и канал ntfy.

## Совместимость

- Звонки и чаты совместимы с клиентами v35: типы сообщений, топики MQTT и
  API Worker не менялись (кроме `/health`). Клиент v36 работает и с Worker v32.
- **Коды и короткие ссылки, созданные в v36, клиент ≤ v35 не откроет**
  (он ищет только старый адрес). Клиенты обновляются сами при открытии
  сайта; до этого пусть собеседник обновит страницу.
- Новых миграций Durable Objects нет.

## Остаточные риски

1. **Нет TURN — нет видео через «жёсткий» NAT.** Пока владелец не задал
   секреты TURN, такие звонки идут через мост (голос, задержка выше).
2. **Метаданные видны инфраструктуре.** Cloudflare, публичные MQTT-брокеры,
   Nostr-реле и ntfy видят IP-адреса, время и объём трафика, хэши комнат;
   Nostr хранит шифротекст публично. Содержимое защищено (а храповик
   защищает прошлую переписку при утечке ключа), но граф связей по
   трафику частично восстановим. Снижение — VPN/Tor у пользователя.
3. **Публичные ретрансляторы ненадёжны.** Из среды сборки Nostr отвечал
   429/521, `test.mosquitto.org` был недоступен; у ntfy анонимные лимиты.
   Архитектура переживает отказ любых каналов, но не всех сразу при
   заблокированном Worker.
4. **Блокировка доменов** `github.io` и `workers.dev`. Снижение: свой домен
   для Worker (Custom Domain), зеркало сайта, установленное PWA открывается
   офлайн.
5. **Доверие к коду сайта.** Целостность клиента = безопасность аккаунта
   GitHub: включите 2FA и защиту ветки `main`.
6. **`/turn` выдаёт ключи любому клиенту** (лимит 20 запросов в минуту с IP,
   ключи живут 6 ч). Возможен расход квоты — следите за ней в панели.
7. **Старые записи кодов** (≤ v35) живут по быстрому адресу до своего TTL,
   постоянные короткие ссылки — до перевыпуска. Перевыпустите важные
   короткие ссылки.
8. **Минимальные браузеры:** Chrome/Android WebView ≥ 80, Safari ≥ 14,
   Firefox ≥ 74; более старые получают экран «обновите браузер».
9. **Push** на iOS/Android в полях не проверялся.
10. **Mesh-группа** до 6 человек: исходящий трафик растёт с каждым
    участником, на мобильной сети 4+ видеоучастника тяжелы.
11. Независимого внешнего аудита безопасности не было.
