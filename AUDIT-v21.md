# ZVONochek v21 — приватный текстовый чат (фаза 1 мессенджера)

Дата: 30.10.2026. База: v20 (коммит d48fa32). Техплан:
`ZVONochek-MESSENGER-TECHPLAN-v21.md`. GitHub не пушился, Cloudflare
не деплоился, секреты не трогались.

## Что сделано (фаза 1 — вариант 1.1)

- **Крипта (`crypto.js`, только добавления)** — `deriveChatKeys(seedBytes, opts)`:
  HKDF-SHA256, salt `ZVONochek/chat/v1`, раздельные info-метки → `roomId`
  (hex 64), `roomKey` (AES-256-GCM, невыгружаемый), `accessToken`
  (сервер хранит только SHA-256). В `opts` заложены хуки фазы 2 (`pinIkm`)
  и фазы 3 (`epoch` — входит в метку ключа, Room_ID и токен от эпохи не
  зависят). `encryptChatMessage/decryptChatMessage`: паддинг plaintext до
  ровно 4096 байт (2 байта длины + JSON + случайный паддинг), blob =
  nonce(12)‖ct = **4124 байта**; `hashChatBlob` — SHA-256 для дедупа.
- **Подписи и идентичность (`identity.js`, только добавления)** — формат
  сообщения `{v:1, id, ts, nick, devPub, type, text, sig}`, подпись ECDSA
  P-256 по канонической строке `zv-chat-v1|id|ts|devPub|type|text`.
  Личная идентичность v20 переиспользуется; гостю без неё создаётся
  локальная пара устройства (`devices/guest`, без сертификата, TOFU).
  Добавлены `encryptWithVault/decryptWithVault` (seed комнаты в IndexedDB
  шифруется тем же vault-ключом, что и секрет личной ссылки).
- **Хранилище (`store.js`)** — DB_VERSION 1→2, сторы `rooms` и `messages`
  добавлены в STORES; существующая миграция создаёт только отсутствующие
  сторы, данные v20 не трогаются.
- **Сервер (`worker/chat-room.js`, новый)** — класс `ChatRoom` в стиле
  `worker/inbox.js`. Таблицы `meta` (access_token_hash), `messages`
  (seq, hash UNIQUE, blob, ts, acked_at), `subs`. Эндпоинты: `POST /init`
  (установка хэша токена, идемпотентно; чужим токеном — 403), `POST /msg`
  (размер blob строго 4124, дедуп по hash → `dup:true`, rate-limit
  60/мин/комнату → 429, рассылка по WS, push wake-up пустым payload
  `{t:'chat', room}` через существующий `push.js`), `GET /fetch?after=`,
  `POST /ack`, `WS /listen` (Hibernation API; auth первым сообщением —
  браузерный WebSocket не умеет заголовки). Все эндпоинты кроме `/init`
  требуют `X-Access-Token` (иначе 401). Retention alarm (раз в сутки):
  ack + 7 дней или 30 дней жёстко — выбор фазы 1 зафиксирован в техплане.
- **Воркер (`worker/worker.js`)** — роут `/chat/<roomId>/…` → биндинг
  `CHAT_ROOMS`, в `/health` добавлены `v:21` и `chat: !!env.CHAT_ROOMS`,
  в CORS allow-headers добавлен `X-Access-Token`. Оба `wrangler.toml`:
  биндинг `CHAT_ROOMS` + миграция `v3` (new_sqlite_classes: ChatRoom).
- **Клиент (`chat.js`, новый)** — создание комнаты (`#chat=<seed43>`,
  фрагмент не конфликтует с `#k=&d=` личной ссылки и звонковыми `#k=`),
  открытие по ссылке, микро-регистрация (никнейм, сохраняется в `rooms`),
  intro-сообщение с закреплением собеседников (TOFU), отправка/приём
  (WS + докачка `/fetch` при reconnect и `visibilitychange`), дедуп по
  хэшу, проверка подписей (неподтверждённые помечаются в UI), история из
  IndexedDB, кнопка «Позвонить» (создаёт обычную звонковую комнату
  существующим путём и постит `system`-приглашение), кнопка «Сменить
  эпоху» — честная заглушка фазы 3.
- **UI (`index.html`, `style.css`)** — блок «Приватные чаты» на главной
  (создать / войти по ссылке / список комнат) и экран комнаты `#chatroom`
  в существующих классах Soft Neon; новых дизайн-концептов нет.
  `sw.js`: кэш v21, `chat.js` в CORE, push типа `chat` показывает пустое
  по смыслу уведомление «Новое сообщение» (без текста и никнейма).
- **Проводка `app.js`** — одна ветка в `route()`: фрагмент `chat=` уходит
  в chat.js, звонковая маршрутизация не затронута; подъём версии
  (APP_VERSION 21, APP_BUILD 2026-10-30, `?v=21`).

## Что НЕ сделано (сознательно)

- Фазы 2 (вариант 1.2: PIN через PBKDF2 600k, контрольные слова,
  per-IP rate-limit для `/chat/`) и 3 (эпохи) — только спроектированы
  в техплане, интерфейсы под них заложены.
- Деплой воркера (нужны миграция v3 и биндинг CHAT_ROOMS в Cloudflare)
  и включение push в проде (секрет VAPID — шаг владельца с 27.10).
- Вложения, чанкинг сообщений длиннее ~3,5 КБ, синхронизация истории
  новому устройству сверх retention-окна сервера.
- Живой тест в браузерах/на устройствах и реальный Cloudflare runtime
  (WS Hibernation, SQLite DO) в этой среде недоступны — см. вопросы.
