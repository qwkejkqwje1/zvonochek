# Cloudflare Worker ZVONochek (v39)

«Слепой» сервер: хранит и пересылает только шифротекст, ключей не знает.

| Файл | Назначение |
|---|---|
| `worker.js` | маршрутизация, CORS, `/health`, `/turn`, комнаты сигналинга (Room) |
| `chat-room.js` | чат-комната (ChatRoom): сообщения, файлы, прочтения, presence, push чата |
| `inbox.js` | дозвон на личную ссылку и из чата, пропущенные, push звонков (Inbox) |
| `pairing.js` | коды, короткие ссылки, кодовые фразы, резервные копии, служебный ключ VAPID (Pairing) |
| `push.js` | Web Push (RFC 8291/8292): шифрование payload и VAPID на чистом WebCrypto |

## Деплой

Из корня репозитория: `npx wrangler deploy` (корневой `wrangler.toml`,
`main = "worker/worker.js"`). Для Workers Builds с корневой папкой `worker`
есть `worker/wrangler.toml` — он совпадает с корневым, кроме пути `main`
(это проверяет `npm test`). Локально: `npm run worker:dev`.

Новых Durable Objects и миграций в v38–v39 нет: деплой поверх v32–v38
безопасен, данные сохраняются.

## Переменные и секреты

Все необязательны.

| Имя | Что это |
|---|---|
| `ALLOWED_ORIGINS` | сайты через запятую, которым отвечает Worker; пусто — любой (только для разработки) |
| `VAPID_PRIVATE_JWK` | свой приватный ключ push (JWK P-256). С v38 не нужен: без него ключ создаётся сам |
| `VAPID_SUB` | контакт для push-служб в JWT (`https://…` или `mailto:…`), по умолчанию — адрес репозитория |
| `TURN_URLS` + `TURN_USERNAME` + `TURN_CREDENTIAL` | любой TURN со статическим логином (свой coturn, Metered, ExpressTURN) |
| `METERED_DOMAIN` + `METERED_API_KEY` | Metered.ca (`METERED_API_TOKEN` — синоним ключа) |
| `TURN_KEY_ID` + `TURN_KEY_API_TOKEN` | Cloudflare Realtime TURN (нужна привязанная карта) |

Секреты задаются `npx wrangler secret put <ИМЯ>` или в панели
Cloudflare → Worker → **Settings → Variables and Secrets**.

**Push без настройки (v38).** Если `VAPID_PRIVATE_JWK` не задан, при первом
запросе Worker создаёт пару P-256 и хранит её в служебном Pairing DO
(`idFromName('zv-vapid-v1')`, внутренний путь недоступен снаружи).
Публичный ключ отдаёт `/push-key`. Если задать или сменить секрет позже,
ключ поменяется: клиенты сравнивают ключ подписки с `/push-key` при запуске
и переподписываются сами. JWT VAPID кэшируется на 11 часов по push-службе.

TURN: с v38 клиент держит статический TURN из `config.js` в резерве и
подключает его только при неудаче прямого пути. `/turn` лишь добавляет
серверы к этому резерву.

## Эндпоинты

- `GET /health` — `{"ok":true,"v":39,"turn":…,"push":…,"pushRepeat":true,"retention":"v38","devices":true,"revoke":true,"linkNx":true,…}`.
- `GET /turn` — временные ICE-серверы:
  - провайдеры опрашиваются параллельно, таймаут 3,5 с;
  - порт 53 отбрасывается, `turns:`/443/TCP идут первыми;
  - не больше 20 запросов в минуту с одного IP.
- `GET /push-key` — публичный ключ VAPID.
- `/room/<id>` — сигнал звонка: WebSocket с кольцевым буфером и
  HTTP-поллинг `GET ?since=` / `POST`, если WebSocket режут.
  `POST /room/delete` — удаление чата создателем (подпись ECDSA).
- `/chat/<roomId>/…` — API чата (подробно — заголовок `chat-room.js`).
  v38:
  - `/msg` принимает `quiet` (служебное без push) и `push:'call'`
    (push «звонок в чате»);
  - `POST /unsub` снимает push-подписку устройства.
- `/inbox/<topic>/…` — `<topic>` это 16–64 hex или `chatdial-<64 hex>`
  (дозвон из чата, до v38 маршрут его отвергал). Пути:
  - `POST /register` — устройство с сертификатом и push-подпиской
    (v39: отвязанное устройство — 403 `revoked`);
  - `WS /listen` — первым сообщением `auth`, ответ `auth-ok` или
    `auth-fail` с закрытием 4001 (v38, раньше молча);
  - `POST /ring` — звонок; `404 no owner`, если у номера нет устройств;
  - `GET /ring/<id>` — состояние звонка;
  - `POST /ring/<id>/ack` и `POST /ring/<id>/answer` — «звонит», «принят»,
    «отклонён», «отменён» (до v38 всегда 404);
  - `GET /missed`, `POST /missed/ack` — пропущенные;
  - `GET /devices` — устройства номера;
  - `POST /retire` — отзыв номера («Сменить номер» / «Стереть всё», v38);
  - `POST /revoke` (v39) — отвязать одно устройство профиля, не гася номер:
    `{target, ts, sig, by}`, подпись над `revoke|<topic>|<target>|<ts>`
    ключом master (`by:'master'`, плюс `masterPub`), ключом фразы
    восстановления (`by:'recovery'`, плюс `recoveryPub`, `recoveryCert`)
    или самого устройства (`by:'self'`). Устройство помечается revoked,
    его WebSocket закрывается с кодом 4003, повторная регистрация — 403.
- `/pair/create|claim|alias|revoke|word` — коды, алиасы (`renew:true` —
  продление владельцем), кодовые фразы. v39: `/pair/create` с `nx:true` —
  только если по адресу нет живой записи, иначе 409 (запрос и ответ
  привязки устройства не перехватить вторым ответом). `/pair/backup` — резервная копия:
  `PUT` — залить, `GET` — получить, `POST {del:true}` — удалить
  (v38; подпись над `zv-backup-delete-v1|idHash|ts`, ts ± 10 мин).

## Push

- Звонок на номер: через 3 с — push всем устройствам, которые ещё не
  подтвердили входящий (`ack`), повторы — через 20 и 45 с. TTL — до конца
  вызова (90 с). Принят, отклонён, отменён или истёк — остальным устройствам
  уходит `ring-done` (уведомление гаснет или становится «Пропущенным»).
- Сообщения чата: от одного отправителя не чаще раза в 4 с, TTL 6 ч.
  Служебные (`quiet`) — без push. Звонок в чате — TTL 60 с.
- Payload — только `{t, topic, ringId}` или `{t, room}` (хэш-префикс
  комнаты). Ни текста, ни имён. Мёртвые подписки (404/410) удаляются.

## Автоочистка (v38)

Alarm каждого Durable Object удаляет данные по срокам:

| Данные | Срок |
|---|---|
| Сообщения чата | ack от всех устройств, активных за 30 дней, и прошло 7 дней; не позже 30 дней |
| Чат без сообщений и файлов (вся комната) | 30 дней, остаётся только метка «удалён» (410) |
| Пульс группового звонка | 15 минут (`ttlSec`) |
| Код приветствия / кодовая фраза | 15 минут / 24 часа, одноразовые |
| Алиас (короткая ссылка) | 30 дней без выдач и продлений |
| Inbox номера, к которому не подключалось приложение владельца | 30 дней, с push-подпиской — 90; список блокировок сохраняется |
| Пропущенные звонки | 24 часа |
| Резервная копия личности | 180 дней без перезаливки (клиент перезаливает раз в неделю) |
